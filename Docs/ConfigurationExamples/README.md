# Configuration examples

| File | What it is |
|---|---|
| `adrian.gorillatag.steamvrbodytracking.cfg` | Example of the BepInEx startup options file, with defaults. BepInEx creates the real one on first launch. |
| `defaults.trackers.json` | What **Restore defaults** + **Save** writes: no trackers, default preferences. |
| `example.trackers.json` | Three saved trackers: a calibrated waist tracker, a left-elbow tracker with a 4 cm offset, and a left-foot tracker (marker only). |

The JSON files were generated by the plugin's own serializer (`Tests` runner, `--write-examples`) and re-loaded through the same validation the plugin uses, with 0 repair messages. The serial numbers are placeholders. Real ones come from SteamVR (`Prop_SerialNumber_String`, usually `LHR-XXXXXXXX`).

## JSON fields

- `ModEnabled`: dashboard master switch.
- `Trackers[]`, keyed by `Serial` (never by device index):
  - `Role`: one of `Unassigned, Waist, Chest, LeftFoot, RightFoot, LeftKnee, RightKnee, LeftElbow, RightElbow, LeftHip, RightHip, Custom`
  - `Enabled`, `ShowMarker`
  - `PositionOffset` (metres, tracker axes, ±0.5)
  - `RotationOffset` (degrees, Unity Euler, ±180)
  - `Smoothing` (0–0.95)
  - `Calibration` (mount rotation, head-relative position, role at calibration, UTC time)
- `Calibration`: global capture info (valid flag, time, forward yaw, tracker count, rig yaw offset).
- `Ui`: menu distance/scale/always-on-top/follow, marker visibility/through-walls/labels/size.
- `Avatar`: avatar integration on/off, drive torso, drive elbows, max torso angle.

Invalid values found on load are clamped or reset, and every repair is logged and shown. Unknown roles become `Unassigned`. Entries with empty or duplicate serials are dropped. If the main file is unreadable, `.bak` is used. If both are unreadable, defaults are used and the files are left untouched until you press **Save**.
